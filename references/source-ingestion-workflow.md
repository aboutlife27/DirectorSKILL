# 长篇来源继承工作流

## 道：来源不是正史

来源继承的目标是让每个改编判断都能回到稳定证据，而不是把旧系统中的所有推论原样升级。小说正文是不可覆盖的来源；旧角色、场景、道具、剧本和分镜只是候选；经章节证据复核并通过项目审批门的版本，才是当前改编正史。

## 法：四层来源协议

| 层 | 内容 | 权限 | 可否自动晋升 |
|---|---|---|---|
| L0 私有来源 | 分章正文、合订本、源元数据 | 只读、内容哈希标识 | 否 |
| L1 来源清单 | 章节顺序、字符数、文件哈希、语料哈希 | 可复核 | 不适用 |
| L2 候选资产 | 旧人物、场景、道具、剧本、分镜 | `import_status: candidate` | 否 |
| L3 改编正史 | 故事圣经、视觉宪法、已验收资产和镜头 | 版本化、审批门控制 | 仅按批准规则 |

一部作品只能有一个当前 L3。源数据库可以保留为证据，但不能与制片项目并列成为两个当前状态源。

## 术：可验证导入循环

1. **触发：** 用户指定源数据库、剧目 ID、预期标题和私有项目目录。
2. **判定：** 只读检查数据库、剧目、章节非空、序号唯一与连续性。
3. **约束：** 只查询代码中的表与字段白名单；不读取配置、密钥、日志、媒体 URL 或本地路径。
4. **执行：** 用 SQLite backup API 固定一致视图，在临时目录生成 L0–L2；先发布不可变内容和版本清单，复验后只原子切换一个 `current.json` 指针。
5. **观测：** 核对章节数、序号范围、语料哈希、每章文件哈希和五类候选数量。
6. **回滚：** 任一步失败都不更新 `current.json`，旧状态保持可验证；正文与候选集合均相同才返回 `unchanged`，候选变化形成新版本。

导入后先从最小试片范围验证创作链。例如用户只要第一章五个 5 秒镜头，就只读取第一章、建立该 25 秒片段的轻量视觉宪法和镜头包，不编译全书任务图。

## 器：Huobao 导入命令

导入：

```bash
python3 scripts/import_huobao_novel.py \
  --db /path/to/huobao_drama.db \
  --drama-id 2 \
  --output /path/to/private-project \
  --expected-title 十日终焉
```

离线复验：

```bash
python3 scripts/import_huobao_novel.py \
  --output /path/to/private-project \
  --verify-only
```

命令 stdout 始终输出 JSON。业务校验失败返回错误码、阶段和不含正文的消息；`--verify-only` 不读取或修改 Huobao 数据库。

## 候选晋升规则

候选资产进入 L3 前必须同时满足：

1. 有明确章节 ID 和可定位的原文事实支持；跨章综合结论列出覆盖范围。
2. 将事实、合理推论和创作改写分栏，不把模型补全写成来源事实。
3. 与当前故事圣经、人物身份串、空间拓扑和视觉宪法无冲突。
4. 通过对应审批门；被替代版本保留血缘，不覆盖历史。

短试片可以新建局部候选，不需要先批准全书故事圣经，但所有人物、空间、色调、镜头方向和动作终点仍要在五个镜头间逐字继承共同锚点。

## 私有边界

- 小说正文、数据库、合订本、媒体对象、环境文件和服务凭据只留在仓库外的私有项目。
- 公开仓库只保存通用导入器、测试、协议和不含正文的合成样例。
- 不复制源项目提取脚本；即使脚本与正文无关，也要先排除硬编码密钥和本地路径。
- 提交前扫描正文长片段、常见密钥格式、数据库和媒体文件；发现命中先阻断提交。

## 验收清单

- `--verify-only` 通过，当前指针、清单、章节、合订本和候选导出哈希一致。
- 清单中的所有路径均为项目内相对路径，且不经过符号链接；候选记录自身哈希与集合哈希均通过。
- 章节数、最小/最大序号、空章数、重复数与源库只读查询一致。
- 首章、中间章和末章的正文 SHA-256 从源库独立重算后与清单一致。
- 五类候选数量与白名单查询一致，导出中没有路径、供应商、URL 或密钥字段。
- 制片控制内核登记输入的 SHA-256 与对应私有文件一致。
- 公开 Git 暂存区不含 L0、L2 私有内容或服务凭据。

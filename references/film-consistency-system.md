# 长片视觉一致性系统

多场景叙事、连续生成或已有成片需要续接时读取本文件。一致性不是重复同一种镜头，而是所有变化都来自同一套规则。

## 1. 单一状态源

`project-state.json` 是机器真相。导演手册、场景合同、分镜和提示词可以更易读，但不得各自维护冲突版本。创建项目时复制 `assets/project-state-template.json`；每次验收镜头后运行：

```bash
python3 scripts/validate_project_state.py project-state.json
```

退出码 `0` 表示无阻断错误，`1` 表示状态违规，`2` 表示文件无法读取。

## 2. 三层视觉状态

### 不可变核心 `immutable_core`

整片默认不变：画幅、基础焦段族、相机支撑族、颜色角色、动机光逻辑、质感、空间规则、表演幅度、剪辑和声音原则。它定义影片的身份，不是某一场的情绪。

### 弧变量 `arc`

可以随叙事位置连续变化：镜头尺度、运动强度、光比、饱和度、色温、声音密度、平均镜头长度。每项变化都写成趋势，不写互不相干的场景标签。

### 局部状态 `local/transient`

镜头间需要精确交接：人物位置、姿势、视线、持物手、道具方向、湿度、污损、伤妆、天气、灯具开关、相机位置和屏幕方向。

## 3. 全片视觉弧

长片先规划五个位置：`open → rise → turn → climax → release`。短片仍使用同一结构，但可合并 `rise` 与 `turn`。

每个位置至少回答：

- 构图空间在打开还是收紧？
- 焦段族内部向广角端还是长焦端偏移？
- 运动更自由、更受限还是重新稳定？
- 光比、饱和度和颜色角色如何演变？
- 声音密度与平均镜头长度如何改变？
- 哪一次模式中断值得观众真正感觉到？

变化应可画成一条曲线。若六个段落得到六组无关形容词，说明还没有全片视觉弧。

## 4. 场景视觉合同

每场开拍或生成前写一份合同：

```yaml
scene_contract:
  scene_id: S12
  arc_position: 0.56
  dramatic_function: 权力翻转
  archetype: 审讯
  inherit:
    lens_family: [32, 50, 75]
    camera_support: [tripod, dolly]
    palette_roles: project.visual_constitution.immutable_core.palette_roles
  arc_adjustments:
    scale: 从 50mm 双人关系转向 75mm 单人压缩
    contrast: 比上一场提高半级
  local_state:
    screen_direction: 审讯者朝右，嫌疑人朝左
    prop: 录音笔在桌面中线，红灯熄灭
  overrides: []
  state_resets: []
```

`inherit` 不得重新措辞。`arc_adjustments` 必须是相对上一位置的变化。`local_state` 必须能在画面中检查。

跨场默认继续继承最近 `accepted.observed_end` 的全部状态。若时间、省略动作或地点转换确实改变了某一状态，只能在新场景的 `state_resets` 中逐字段声明 `field`、新 `value` 和 `reason`；空起点或漏写字段不算重置。

## 5. 计划与实际状态

每个镜头记录 `planned_start` 与 `planned_end`。生成后：

- `accepted`：补写 `observed_start` 与 `observed_end`，下一镜头从 `observed_end` 续接。
- `rejected`：不更新正史；保留失败原因供修复。
- `repair`：标明修复后是否成为新的 `accepted` 祖先。
- `planned`：仍从最近的已验收实际终点推导，而不是盲信早期计划。

已验收成片是物理事实。计划与成片冲突时，要么修改后续计划，要么重做该镜头；禁止在文档里假装成片遵守了计划。

延展生成的连续深度默认不超过 2，硬上限 3。超过后用新锚帧重新建立角色、空间和光线，而不是无限继承累积误差。

## 6. 破例预算

破例只允许对应三种事件：叙事转折、POV 断裂、世界规则变化。每条必须包含：

```yaml
- field: camera_support
  value: [handheld]
  reason_category: pov_break
  reason: 身份真相使主角的控制感崩解
  scope: [S42, S43]
  restore_at: S44
```

`reason_category` 由 schema 固定为 `narrative_turn`、`pov_break`、`world_rule_change`，项目文件不能自行增删。`scope` 必须从声明场景开始，按项目顺序列出连续、真实存在的场景；其中每场都要显式继承破例值。`restore_at` 必须是 scope 后紧邻的真实场景，并把该字段显式恢复为视觉宪法中的 canonical 值。

默认每幕最多一次。破例越多，观众越无法区分“意义”与“漂移”。高潮不必同时改变焦段、画幅、色彩、运动和剪辑；选择最能承载转折的一项即可。

## 7. 漂移检查

### 阻断错误

- 缺少视觉宪法或不可变核心。
- 改变核心字段却没有登记破例。
- 破例没有原因、范围或恢复点。
- 作用域不是连续真实场景，或恢复场景没有显式回到 canonical 值。
- 下一镜头计划起点与上一验收镜头实际终点冲突。
- 一幕内破例数量超过预算。

### 人工审美检查

- 变化是否沿全片弧前进，而非来回随机摆动？
- 颜色是否仍承担同一叙事角色？
- 相机运动是否仍稀缺到具有意义？
- 极端镜头尺度是否被留给真正的戏剧峰值？
- 重复构图是有意回响，还是缺少覆盖想法？
- 本场漂亮画面是否破坏了整片更重要的视觉承诺？

## 8. 工作循环

1. 全片只做一次视觉宪法和五段视觉弧。
2. 只编译下一个尚未解决的场景，不一次生成整片全部提示词。
3. 场景先继承，再写弧变化，最后才考虑破例。
4. 分镜逐镜声明计划起止状态。
5. 生成或拍摄后只验收可用镜头。
6. 用验收镜头的实际终点更新正史。
7. 运行确定性检查，再进行人工审美检查。
8. 把项目状态压缩成下一轮所需的场景胶囊，避免长上下文重述造成漂移。

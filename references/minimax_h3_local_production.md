# MiniMax H3 本地制片调用基线

## 已验证结论

- 使用 `MiniMaxH3ImageToVideo`，把角色、服装、场景、道具和构图先合成为批准首帧，再让 H3 只负责时间变化。
- 当前 ComfyUI `MiniMaxH3ReferenceToVideo` 的 API 参考图输入会被忽略，禁止作为角色一致性路径。
- 文本动作条件有效，但模型可能放大动作幅度；每个镜头只写一个主动作，并做语义 QC。
- 节点声明的训练范围约为 124–362 帧（24 fps，约 5.17–15.08 秒）。接口的 3600 帧上限不是已证明能力。

## 生产档位

| 用途 | 分辨率 | 默认帧数 | 实测耗时 | 使用规则 |
|---|---:|---:|---:|---|
| 动作预演 | 608×352 | 124 | 低成本 | 只审动作、运镜和构图，不审最终细节 |
| 常规生产 | 960×544 | 124 | 176.3 秒 | 当前默认档，批准后再升级 |
| 最终镜头 | 1344×768 | 124 | 516.5 秒 | 只生成已批准镜头，避免昂贵返工 |
| 长镜头试验 | 608×352 | 362 | 235.5 秒 | 接近训练上限，必须检查中段和尾帧 |

481 帧（20.04 秒）在 608×352 下能够完成，但已观察到背景重建和额外口型，不进入默认生产档。

## 一致性协议

1. 资产部门生成角色、场景和道具资产，并形成不可变版本。
2. 分镜部门选择景别、机位、焦段、光线和色调，合成镜头批准首帧。
3. 运动提示只描述单一主动作、固定项和禁止项，不让视频模型重新设计画面。
4. 验证器将首帧上传为内容寻址副本，并把同一个 `LoadImage` 输出同时送入 H3 与 `SaveImage`。
5. 完成后核对实际加载首帧像素、输出帧数、时长、解码流哈希和动作语义。
6. 失败镜头回到首帧或运动提示层修正；不通过堆叠提示词掩盖资产问题。

## 调用工具

- `scripts/validate_comfyui_h3_reference.py`：验证首帧/参考图条件是否真正生效。
- `scripts/validate_comfyui_h3_prompt.py`：用固定种子 A/B 验证动作提示是否真正生效。
- `scripts/probe_comfyui_h3_duration.py`：递增探测时长与分辨率，支持断点和证据复核。

示例：

```bash
python3 scripts/probe_comfyui_h3_duration.py \
  --base-url http://COMFYUI_HOST:8189 \
  --image-name approved-first-frame.png \
  --output-dir work/h3-probe \
  --lengths 124 362 \
  --width 960 \
  --height 544
```

## 人工门

- 首帧必须先批准角色身份、服装、场景、道具、构图和色调。
- 成片必须检查身份漂移、背景重建、额外动作、口型、手部、道具接触和尾帧可接续性。
- 多人遮挡、全身走位、复杂运镜和高分辨率长镜头尚未验证，不能自动批准。

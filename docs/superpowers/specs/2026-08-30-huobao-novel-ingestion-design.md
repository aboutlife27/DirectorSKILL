# Huobao 长篇小说继承设计

## 目标

把 Huobao Drama 中已有的长篇小说、章节元数据和派生制作资产继承到本地制片控制系统，形成可追溯、可复核、可继续改编的项目底座。导入完成不等于剧本改编完成；它只证明源材料与候选资产已经稳定进入项目，并可供后续故事圣经、改编结构、视觉宪法和样片任务消费。

首个实际项目为《十日终焉》。已观察事实如下：

- 有效源数据库为 `/Users/apple/Projects/huobao-drama/data/huobao_drama.db`；同目录带连字符的数据库是空文件。
- `drama_id=2`，标题为《十日终焉》。
- 章节记录共 1384 条，`episode_number` 从 1 到 1384 连续、无重复、无空正文。
- 正文总计 3,209,419 个 SQLite `LENGTH` 字符单位；最短 1840，最长 14809。
- Huobao 已有 121 个角色、142 个场景、9 个道具；已有剧本只覆盖 1 个章节，已有分镜覆盖 2 个章节。
- 章节展示标题存在序号偏移，因此排序与稳定标识必须使用 `episode_number`，标题只作为原始元数据保存。
- SQLite `integrity_check` 返回 `ok`。尚无独立外部版本用于证明其与出版或连载终版逐字一致。
- Huobao 的部分提取脚本含硬编码服务密钥，脚本不得复制到新项目，密钥不得进入任何导出物、日志或 Git 历史。

## 原则

1. **原文是只读证据，不是可编辑工作稿。** 导入后以内容哈希标识，每次改编只生成新资产，不覆盖原文。
2. **来源与推论分离。** 章节正文属于来源层；Huobao 的人物、场景、道具、剧本和分镜属于候选层；经复核接受的故事圣经和剧本才属于改编正史。
3. **本地私有与公开代码分离。** 小说正文、数据库快照和可能包含大段原文的导出物只保存在本地私有项目。公开仓库只保存通用导入器、测试、格式说明和不含正文的示例。
4. **可重复、可中断、可验证。** 导入由脚本执行，支持同一语料幂等重跑，失败不发布半成品，并输出机器可读错误和验证报告。
5. **一部作品一个正史。** 后续视觉、角色、场景、道具和镜头状态统一进入同一个制片项目，不让 Huobao 数据库与制片状态并列成为两个当前真源。

## 方案选择

采用“规范化快照导出”，不直接把 Huobao 数据库作为运行时依赖，也不立即重跑全书 AI 提取。

- 直接复制数据库虽然最快，但会把 Huobao 表结构、配置和潜在敏感数据一并耦合进项目，无法清晰区分原文与派生资产。
- 立即重跑全书提取会在改编形态尚未锁定时产生大量费用和不可验证推论，并放大已有错误。
- 规范化快照只导出白名单字段，以章节哈希和语料哈希固定来源，同时保留后续重新提取的空间。

## 数据分层

### L0：私有源材料

目录 `source/private/snapshots/<corpus_sha256>/` 保存：

- `chapters/CH0001.md` 至 `chapters/CH1384.md`：UTF-8 正文，文件头保存稳定章节 ID、数据库 episode ID、顺序号和原始标题。
- `compiled-novel.md`：按稳定顺序拼接的模型输入版本，用于制片控制内核登记；其内容不进入 Git。
- `source-metadata.json`：源数据库路径、数据库文件哈希、语料哈希、导入时间、剧目 ID、标题和统计。

`corpus_sha256` 由按顺序排列的章节稳定字段和正文内容计算，不依赖数据库修改时间或无关表。

### L1：来源清单

目录 `source/manifests/versions/<state_sha256>/` 保存不含正文的 `novel-manifest.json` 与 `verification-report.json`：

- 每章包含稳定 ID、源 episode ID、顺序号、原始标题、字符数、正文 SHA-256。
- 全局包含章节数、最小/最大顺序号、语料哈希、空章数、重复序号数和连续性结论。
- `current.json` 是唯一可变指针，原子指向当前接受的版本清单；路径必须留在项目目录内且不得经过符号链接。

清单默认留在私有项目。若未来公开，只能在确认标题等元数据也允许公开后另行生成脱敏版本。

### L2：Huobao 候选资产

目录 `imports/huobao/<corpus_sha256>/<candidate_set_sha256>/` 保存白名单 JSON：

- `characters.json`
- `scenes.json`
- `props.json`
- `existing-scripts.json`
- `existing-storyboards.json`

每条记录附加 `source_table`、`source_id`、`source_drama_id`、`source_episode_id`（若有）、`import_status: candidate` 和记录哈希。删除时间、供应商配置、服务密钥、生成服务凭证、日志和非本剧目记录均不导出。

### L3：改编与制片正史

私有项目使用现有制片控制内核：

- `.production/production.db`：任务、运行、候选、评审和审批门。
- `media/objects/`：按内容哈希保存登记输入与后续媒体。
- `project-state.json`：人物、场景、道具、视觉宪法和已验收镜头状态。

L2 候选不能自动写入 `project-state.json`。只有经过原文章节证据复核并被接受的资产，才能成为 L3 正史。

## 导入器合同

通用命令：

```bash
python3 scripts/import_huobao_novel.py \
  --db /path/to/huobao_drama.db \
  --drama-id 2 \
  --output /path/to/private-project \
  --expected-title 十日终焉
```

行为约束：

1. 以只读连接打开源数据库，并使用 SQLite backup API 取得一致快照。
2. 检查必需表和字段、剧目存在性、标题、章节非空、编号唯一与连续性。
3. 只读取白名单表和白名单字段，拒绝导出 AI 服务配置或脚本。
4. 在目标目录的临时兄弟目录中完成全部写入；正文、候选与版本清单以不可变目录发布并复验，最后只原子替换一个 `current.json` 指针。
5. 正文和候选集合哈希均相同时返回 `unchanged`；同一正文的候选集合变化时创建新状态版本，不覆盖旧版本。
6. 所有成功和失败输出 JSON；失败包含稳定错误码、阶段和可操作信息，不输出正文或敏感字段。
7. 提供 `--verify-only`，只验证现有快照与清单，不读取或改写 Huobao 数据库。

## 制片项目初始化

首个私有项目目录为：

`/Users/apple/Documents/Codex/2026-08-11/jin/work/ten-day-terminus-production`

初始化顺序：

1. 创建私有目录和 `.gitignore`，排除 `source/private/`、`.production/`、`media/`、导出成片、数据库和环境文件。
2. 运行导入器，生成 L0、L1、L2。
3. 使用制片控制 CLI 初始化项目 ID `ten-day-terminus`、标题《十日终焉 AI 影像改编实验》。
4. 登记 `compiled-novel.md`、来源清单和五类 Huobao 候选资产；每个输入由控制内核复制并记录 SHA-256。
5. 按用户确定的最小实验范围，只用第一章建立 5 个 5 秒镜头的生成包，并作为第八项输入登记。
6. 暂不导入完整生产任务图；先用每天五次免费生成额度验证镜头可生成性和跨镜一致性。

## 后续改编流程

继承完成后按以下顺序推进，不把 320 万字符一次塞给模型：

1. 逐章提取可验证事实、人物行动、地点、道具、时间信息、谜题与揭示，保留章节引用。
2. 按故事弧进行分段综合，再做全局人物关系、世界规则、时间线和伏笔回收审计。
3. 形成故事圣经与改编候选结构，明确删并改的依据和不可破坏的核心体验。
4. 选择一个代表性片段制作剧本、资产和样片，实测身份一致性、空间连续性、动作可生成性、成本与修复率。
5. 样片通过后再锁定系列短剧、剧集或长片结构，并编译全量制片任务图。

## 失败与恢复

- 源数据库缺表、损坏、剧目不存在、标题不符、章节为空、编号重复或不连续：阻断导入，不发布快照。
- 临时写入、路径安全或哈希复核失败：不切换 `current.json`，旧状态继续可验证；未被引用的不可变目录可由后续同内容重试复用。
- 同一快照再次导入：不重复写正文；重新验证全部哈希后返回原快照。
- Huobao 候选字段含无效 JSON：保留原始字符串及解析错误标记，不把解析猜测写成事实。
- 制片登记失败：来源快照仍有效；修复制片项目后可按清单幂等重新登记。

## 验收证据

导入完成必须同时满足：

- 导入器测试覆盖正常导入、错误数据库、标题不符、空章、重复/缺失编号、幂等重跑、候选变更、原子失败、路径逃逸、符号链接、敏感表隔离和现有快照验证。
- 《十日终焉》导入报告显示 1384 章、编号 1–1384、无空章、无重复序号、语料哈希稳定。
- 随机首章、中间章和末章的导出文件哈希能由数据库正文重新计算得到。
- 五类候选资产的导出数量与数据库白名单查询一致。
- 制片控制内核列出的登记输入 SHA-256 与导入清单一致。
- 第一章试片包恰含 5 个 5 秒镜头，每个生成提示都继承同一视觉锚点。
- `git status` 和提交内容证明公开仓库中不存在小说正文、源数据库、服务密钥或私有媒体。

## 非目标

- 本阶段不声称 Huobao 文本与任何外部终版逐字一致。
- 本阶段不自动批准 Huobao 的角色判断、场景设计、剧本或分镜。
- 本阶段不决定最终改编为多少集、每集时长或完整长片。
- 本阶段不调用付费模型、不生成图像或视频，也不启动无人值守批量生产。

# 自动视觉导演与长片一致性设计

## 目标与边界

### 道：本质目标

让 skill 根据剧情证据自动作出可解释、可执行的导演决策，同时让同一部影片从开场到结尾像出自同一个创作意志。默认输出唯一方案；仅当关键输入缺失、最高候选与次高候选差距小于 10 分，或改动会突破项目级视觉宪法时请求选择。

### 硬约束

- 同一证据与同一项目状态必须得到稳定的核心策略。
- 先决定观众应知道和感受什么，再决定构图、镜头、色彩与运动。
- 项目只有一个机器可读的视觉状态源。
- 重大转折允许受控破例，但必须记录原因、作用范围和恢复点。
- 已验收成片高于原计划；后续镜头从实际成片状态续接。
- 不自动模仿在世导演。大师方法被拆成可解释的功能原则。

### 可验证成功标准

1. 未指定导演时，方案仍能从剧情证据推出场景原型、覆盖方式、色调和摄影手法。
2. 六段以上长片规划具有明确的视觉弧，而不是六套独立风格。
3. 相邻镜头的计划起止状态可衔接；验收镜头能回写实际状态。
4. 无理由改变焦段族、机位语法、主色角色或光线逻辑会被检查器报错。
5. 多位导演偏好冲突时，系统按戏剧目标选择功能方法，而非拼贴风格。

## 方案比较

### A. 扩充类型查表

把悬疑、爱情、动作等类型映射到固定镜头、色调和节奏。实现最快，但同一类型内部的戏剧功能差异无法解释，长片容易成为模板拼接。

### B. 剧情到视觉的决策编译器（采用）

先生成结构化导演读法，再对场景原型评分，随后在项目视觉宪法约束内编译成视觉策略。它兼顾自动化、可解释性与长片一致性，且能在模型和制作工具之间保持中立。

### C. 组合多个市场 skill

分别让导演、摄影、分镜、连续性 skill 接力。单项能力可能更强，但状态所有权冲突、上下文漂移和供应商依赖会破坏长片一致性，因此只吸收其方法，不安装为核心链路。

## 系统设计

```text
剧情/剧本
  -> 导演读法（戏剧功能、转折、POV、信息差、权力、压力）
  -> 项目视觉宪法（不可变核心 + 全片视觉弧 + 破例预算）
  -> 场景原型评分（唯一首选 + 置信度 + 备选）
  -> 场景视觉合同（继承值 + 本场变化 + 有因覆盖）
  -> 分镜编译（覆盖语法、构图、焦段、运动、光色、声音、剪辑）
  -> 生成/拍摄
  -> 验收镜头回写（计划状态 vs 实际状态）
  -> 连续性与风格漂移检查
```

### 1. 导演读法

每场至少记录：`dramatic_function`、`turn`、`pov`、`audience_information`、`power_in/out`、`objective`、`obstacle`、`tactic`、`subtext`、`pressure_delta`、`visible_behavior`。抽象情绪必须翻译为可见或可听载体。

### 2. 场景原型路由

候选原型为：建立、亲密、对峙、审讯、谈判、揭示、发现、决定、追逐、旅程、氛围、转化、余波。每个候选按八个证据轴评分：视点依附、权力变化、信息控制、亲密距离、动能、时间压力、不确定性、现实感。

最高分为默认方案。分差小于 10、证据存在矛盾或必须突破视觉宪法时，才展示备选并请求选择。输出必须说明前三条决定性证据，不能只报类型。

### 3. 项目视觉宪法

状态分三层：

- `immutable_core`：画幅、基础焦段族、摄影支撑族、色彩角色、对比逻辑、质感、空间与表演规则。
- `arc`：随叙事位置变化的镜头尺度、运动、光比、饱和度、色温、声音密度、平均镜头长度曲线。
- `local`：本场天气、道具、站位、伤妆、动作起止等短期状态。

整片先规划 `open → rise → turn → climax → release` 的视觉弧。局部策略必须继承宪法；破例必须包含 `reason`、`scope`、`restore_at`，且默认每幕最多一次。

### 4. 分镜编译

决策优先级固定为：情绪真相 → 叙事推进 → 节奏 → 观众视线 → 二维构图 → 三维连续性。每个镜头只承担一个首要工作，并记录它如何改变观众的信息或感受。

大师成果被转译为功能方法：

- 信息差与悬念：控制观众比角色早知、同知或晚知，以及揭示前的反应镜头。
- 全片视觉弧：让焦段、机位高度、构图压力和空间感随剧情渐变。
- 色彩写作：颜色承担人物、观念或阶段角色，不把色调当情绪形容词。
- 画内运动：人物、环境和天气分层组织运动，保持动作可读性。
- 深焦与调度：当权力关系依赖同框空间时，优先用调度表达而非任意切碎。
- 剪辑优先级：发生冲突时，情绪与故事高于机械空间连续性，但破坏必须有意。

### 5. 状态回写与一致性检查

`project-state.json` 是唯一机器真相。它区分：

- `canonical`：角色、场景、道具和视觉宪法的长期事实。
- `transient`：当前姿势、持物手、湿度、伤妆、天气、灯具状态、摄影位置。
- `planned_start/end`：分镜预计状态。
- `observed_start/end`：已验收成片的实际状态。

只有 `accepted` 镜头更新下一镜头的真实起点。检查器输出错误、警告和信息三级结果，并以非零退出码阻止结构错误或无恢复点的破例。

## 产物边界

- `SKILL.md`：路由、主流程、唯一方案协议、资源加载规则。
- `references/story-to-visual-compiler.md`：证据轴、原型评分、视觉编译规则。
- `references/film-consistency-system.md`：视觉宪法、视觉弧、状态回写与漂移规则。
- `assets/film-visual-constitution.yaml`：人可读项目规则模板。
- `assets/project-state-template.json`：机器状态模板。
- `scripts/validate_project_state.py`：零第三方依赖的确定性检查器。
- `tests/test_validate_project_state.py`：结构、破例、连续性和漂移回归测试。
- `evals/evals.json`：加入自动选择、长片视觉弧和冲突风格三类行为评测。

## 非目标

- 不调用具体视频生成供应商 API。
- 不替用户完成不可逆的成片定版。
- 不以导演姓名作为自动选择器输出。
- 不试图用一个评分公式取代审美判断；评分负责稳定路由，最终方案仍须解释戏剧理由。
